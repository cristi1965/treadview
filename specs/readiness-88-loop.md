# 专业可用度 88 分闭环合同

## 目标与计分

使用固定 10 个模拟审计角色和固定 8 项评分：数据可信度、研究深度、信号可解释性、
交易可执行性、风险控制、组合管理、效率易用性、审计合规。每项 0-10 分，角色分数按
`sum / 80 * 100` 归一化，最终分为 10 个角色的算术平均。

完成条件同时满足：

1. 十角色平均分严格大于 88/100。
2. 没有高置信度 P0/P1 否决项。
3. 源码测试、独立二进制 API 验收和桌面/390px 浏览器验收通过。
4. 运行证据能关联 PID、二进制、cwd、构建时间和关键响应。

不得通过删除低分角色、改变权重、把纸面交易称为真实成交、把抓取时间称为财报期、
把快照称为实时行情或隐藏外部接口失败来达标。

## 固定模拟角色

1. 公募基金经理 / CIO
2. 基本面研究主管
3. 量化与数据质量审计员
4. 主观交易员
5. 执行交易 / OMS 审计员
6. 独立风险经理
7. 资深牛散
8. 合规与披露审计员
9. 产品运营 / 普通用户
10. 生产运维 / SRE

## 第一轮硬性验收

### 数据与运行状态

- `/api/system/status` 与业务接口的 source、dataTime、stale 和 unavailable 状态一致。
- stale 快照的 `X-Data-Time` 必须来自真实快照或最后成功行情时间，不能使用响应时间。
- 系统状态检查覆盖行情、ETF、Whales 和研究证据，不允许总状态与明细相互矛盾。

### 权限与审计

- 分析启动/停止、配置写入、数据刷新、Whales 同步、交易/事件写入必须受写权限保护。
- 未配置管理凭证时写操作默认关闭；认证失败不执行副作用。
- 写操作形成带 actor、action、target、request ID、时间和结果的审计记录。

### 研究与披露

- 基本面显示财报期间或明确未知，区分数据期间与抓取时间，并提供来源链接/字段来源。
- 分析结果保存输入数据时间、来源、模型/方法版本和可核对证据清单。
- Whales 页面统一 SEC/Dataroma 的真实来源口径；`consensusCount` 只解释为同报告期持有人数。
- 报告期未知时，首屏卡片也必须显示 stale/unknown，不得只在详情下方披露。

### 订单与风险

- 实现明确标注为 paper 的订单生命周期：提交、校验、接受、取消、拒绝、模拟成交和状态查询。
- 每个 paper order 具有 client order ID、不可重复提交、状态变更记录和拒绝原因。
- 无新鲜报价、字段不完整或风险超限时硬阻断；不能复制或提交超限订单。
- UI 不得暗示已连接真实券商或产生真实成交。

### 组合

- 组合风险至少覆盖现金、总敞口、币种、单票/行业集中度、止损覆盖和最大计划亏损。
- 缺报价不计算完整市值与盈亏，风险限制和异常原因可见。
- 本地持仓、提醒和 paper order 的持久化与关闭应用边界明确。

## 循环规则

每轮流程固定为：实现 -> 聚焦测试 -> 全量测试/构建 -> 独立运行态验收 -> 十角色复评。
低于 88 时，按该轮高置信度否决项排序进入下一轮；旧分数不能覆盖新证据。
