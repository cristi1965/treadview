# 专业可用度 70 分：第一阶段实施合同

## 目标

把「我不是神」从线索浏览工具提升为可信的研究与人工下单准备工具。
本阶段目标分为 70/100，沿用以下八项、每项 10 分的评分口径：

1. 数据可信度
2. 研究深度
3. 信号可解释性
4. 交易可执行性
5. 风险控制
6. 组合管理
7. 效率与易用性
8. 审计与合规

70 分不代表专业交易终端、自动交易系统或机构生产系统。本阶段不接券商，
不执行真实订单，不建设完整回测、权限、多账户或不可篡改审计。

## 必须通过的用户行为

### 行情与来源

- 过期、快照、超时或来源未知的价格不能显示为「实时」。
- 报价调用同时返回数据、来源、数据时间、过期状态、原因和缺失代码。
- 无可验证的新鲜报价时，条件单复制和价格提醒触发必须被阻断。

### 人工下单计划

- 订单计划明确方向、市场、币种、订单类型、有效期、入场、止损、止盈和数量。
- 买入数量同时受单笔最大亏损 1.5% 和最大名义仓位 15% 约束。
- 保护止损模式要求输入已有数量，不能反推成买入单。
- 页面预览和复制文本必须由同一个结构化订单对象生成。

### 组合风险

- CNY 与 USD 分开汇总，禁止直接相加。
- 报价不完整时明确显示覆盖率，禁止把缺报价持仓显示为巨亏。
- 展示 Top1、Top3 集中度和单票超限提示。
- 提醒监控在应用任一路由可见时运行；页面明确说明关闭应用不会提醒。

### 研究和聪明钱

- 五方评分明确标注实际方法、版本、生成时间和输入局限，禁止把启发式分数称为真人或逐股 AI 研究。
- 13F 显示报告期、申报日、同步时间和来源；缺失时显示未知并标记不可验证。
- 共识统计必须来自真实返回值；真实 0 显示 0，禁止常量兜底。

## 验收证据

- Go 聚焦单元/契约测试。
- 前端纯函数测试或等价确定性脚本测试。
- 新构建后端运行在独立端口，并执行 `scripts/verify-local.sh` 或等价 API 抽检。
- Playwright 覆盖 fresh、stale、missing 三态，以及桌面和 390px 组合/战术页面。
- 记录运行 PID、可执行文件、cwd 和响应头；当前 `:8765` 旧进程不能作为源码完成证据。
