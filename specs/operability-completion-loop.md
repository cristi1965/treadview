# 可操作性完成 Loop

## 目标

在不引入真实交易、不伪造实时数据、不把凭证写入仓库的前提下，完成 Paper 浏览器生命周期、行情分层刷新、GPU 动态源运维化、ETF 当前/历史模式和移动端关键动作验收。

## 产品边界

- 所有订单仍是 Paper 模拟订单，不连接券商。
- 交易时段内超过 60 秒或覆盖不完整的行情不标记为 live。
- GPU 凭证只从进程环境或仓库外 `0600` 文件读取，API 不返回密钥。
- 未配置外部凭证时，使用确定性 fixture 验证动态链路，但页面必须继续显示 `unconfigured`。
- ETF 刷新失败不覆盖 last-good；历史快照不用于当前决策。

## 验收条件

1. Paper UI 能显式建立日初基线，提交、分笔成交、撤单、OCO 调整、PnL 和审计链均由服务端状态驱动。
2. 行情按 hot/visible/broad 分层；页面无重复 timer，hidden 暂停，恢复可见立即刷新，同层请求有 in-flight 去重。
3. GPU 无凭证启动后可安全重读凭证并开始调度；有可配周期、退避、下次刷新时间与历史保留策略。
4. ETF API 明确区分 `current|historical`，返回年龄、阈值、最近尝试和下次调度；定时任务只原子提升完整新快照。
5. 手机 touch context 覆盖 Paper、GPU、自选、报告、笔记和组合工具的关键动作，无遮挡、横向溢出和未处理异常。

## 循环规则

每个模块先跑聚焦测试，失败则修复并重跑；全部聚焦测试通过后，再跑 Go 全包、前端全部测试/构建、`verify-local.sh`、Paper/GPU fixture 和桌面/手机浏览器验收。
