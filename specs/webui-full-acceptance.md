# WebUI 全量验收规范

## 验收原则

只有同时满足功能、数据、UI/UX 三项，页面才允许标记为通过。路由能打开、构建成功或接口返回 200 都不能单独作为通过证据。

## 证据记录格式

每条用例必须记录：

```text
角色 | 路由 | 视口 | 前置状态 | 操作 | 页面结果 | API结果 | 数据对账 | UI/UX结果 | 结论 | 证据
```

结论只允许：`通过`、`部分通过`、`失败`、`未验证`。

## 角色场景

- [ ] 日内交易员：扫描、筛选、排序、刷新、打开个股、返回列表
- [ ] 量化交易员：切换条件、组合筛选、边界值、清空条件、分页
- [ ] 宏观基金经理：宏观指标、日历、跨市场切换、时间和来源
- [ ] ETF 基金经理：分类、排序、溢价、持仓、详情返回
- [ ] 价值基金经理：个股报价、基本面、财报期次、新闻、K 线
- [ ] 成长基金经理：对决、切换标的、展开全部、分析结果
- [ ] 风险经理：VIX、异常、风险提示、过期和不可用状态
- [ ] 组合经理：新增/编辑/删除前确认、盈亏刷新、持久化、重复提交
- [ ] 事件驱动交易员：盘报、详情、分页、日期、来源和有效期
- [ ] 复盘交易员：新增记录、编辑、取消、保存、重复保存、历史回看

## 功能控件

- [ ] 所有注册路由已打开
- [ ] 所有可见按钮逐个点击并记录结果
- [ ] 所有输入框填写合法值和非法值
- [ ] 所有表单验证成功提交、失败提交、取消和重复提交
- [ ] 所有弹窗打开、关闭、遮罩点击、Escape 关闭
- [ ] 所有抽屉打开、关闭、返回和状态保留
- [ ] 所有 Tab 逐个切换并确认内容变化
- [ ] 所有下拉选项逐项选择并确认结果变化
- [ ] 所有筛选、排序、分页和清空动作
- [ ] 所有跳转、返回、刷新和重新进入
- [ ] 所有保存类动作检查持久化结果
- [ ] 所有外部请求类动作检查处理中、成功、失败、重试和停止

生产数据写入的成功提交必须使用隔离测试数据或经过确认；未执行的写操作必须标记为 `未验证`，不能标记为通过。

## 数据准确性

- [ ] 页面显示值等于对应 API 原始值
- [ ] API 原始值带来源、数据时间、时区和 stale 状态
- [ ] 价格、涨跌额、涨跌幅通过数学关系校验
- [ ] 指数代码、名称、市场和单位匹配
- [ ] 与外部行情源逐项对账
- [ ] 正常行情场景
- [ ] 空数据场景
- [ ] 上游超时场景
- [ ] 上游 403/429 限流场景
- [ ] 上游 500/503 场景
- [ ] 局部成功、局部失败场景
- [ ] 旧快照、未来时间戳、默认 0、mock 和 fallback 扫描

数据失败时必须在页面显示明确状态，禁止继续渲染旧数字或“正常交易中”。

## UI/UX 与文字排版

- [ ] 1440px 桌面
- [ ] 1024px 窄桌面
- [ ] 390px 移动端
- [ ] 无横向溢出和不可点击控件
- [ ] 首屏加载时间和请求数量可接受
- [ ] 加载、空数据、过期、失败、重试状态清晰
- [ ] 中文长标题正确换行
- [ ] 英文代码、数字和单位不被截断
- [ ] 卡片高度稳定，内容不重叠
- [ ] 表格列宽、行距和滚动可读
- [ ] 盘报和 AI 长文本按段落、标题和重点数字排版
- [ ] 数据时间、来源和状态足够醒目
- [ ] 移动端弹窗、抽屉、筛选和长文本可用

## 本轮已知未通过项

1. Yahoo 403/429 时行情总览请求可能等待过久，影响 WebUI 首屏和自动化会话。
2. `/api/macro`、`/api/flash` 曾出现长时间等待或 503，尚未满足故障快速反馈门槛。
3. HSTECH 当前没有可用 Yahoo 行情代码，已显示不可用，但替代源尚未完成。
4. 10 个角色目前是模拟角色，不是真实外部交易员或基金经理。
5. 所有写入型表单的成功提交、重复提交和持久化结果尚未全部完成隔离验证。

## 通过门槛

- 所有清单项均有证据；不存在 `未验证` 的 P0/P1 项。
- 核心行情上游失败后 5 秒内显示不可用或重试状态。
- 页面不显示无来源、无时间、过期未标记或伪造的数字。
- 10 个角色的任务均有操作前后证据。
- 三种视口无阻断级排版问题。
- 任何一项功能、数据或 UI/UX 失败，整体结论不得写成“全部通过”。
